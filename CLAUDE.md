# AgentVpnGuard — инструкции для Claude

Поведение, настройки и ограничения — в `README.md`, прочитать перед правкой.

## Прежнее имя ClaudeVpnGuard (до 3.0)

- `AppIdentity.LegacyName` — прежнее имя. По нему `HostsPinner` снимает старый блок hosts, а установщик
  (`installer\setup\LegacyInstall.cs`) закрывает старую программу, переносит `settings.txt`, согласие и журналы из
  `C:\ProgramData\ClaudeVpnGuard`, снимает группу брандмауэра, задачу Планировщика, запись в «Приложениях» и папки.
  Убирать это нельзя: обновление поверх любой прежней версии обязано работать.
- Каждый Release несёт установщик под двумя именами: `AgentVpnGuardSetup.exe` и `ClaudeVpnGuardSetup.exe`. Второй
  ищет «Проверить обновление…» установленных ClaudeVpnGuard; запросы к старому репозиторию GitHub перенаправляет сам.
- Отчёты о сбоях ClaudeVpnGuard приходят на `/pets/claudevpnguard/crash-report`; сайт принимает их и показывает в
  разделе AgentVpnGuard.

## Сборка

- Штатный `csc.exe` .NET Framework 4.8, **C# 5**: нет `$"..."`, `?.`, `nameof`, `=>`-членов,
  инициализаторов авто-свойств, `out var`.
- `build.cmd` — программа, `build-installer.cmd` — программа, деинсталлятор и установщик в `dist\`.
- Программа требует прав администратора (`requireAdministrator`). Запущенный экземпляр из обычной
  консоли не закрыть: `build.cmd` переименовывает занятый exe в `.old.exe`.

## Проверка

- Защиту по-настоящему ставит только запуск с правами — это делает пользователь. Логику без прав
  проверять обвязкой в scratchpad (`/main:` или отдельный `Main`): адаптеры, поиск exe, DNS через VPN,
  маршруты, чтение таблицы соединений, `HostsPinner` на копии hosts (поле `HostsPath` подменяется
  отражением).
- Скриншоты README (`docs\*.png`) — обвязкой на синтетических данных: без реальных путей и имени
  пользователя. Поменял интерфейс — переснять.
- Сеанс Claude, в котором идёт работа, сам под защитой: ошибка в правилах отрезает этот же тред.

## Правила кода

- Комментариев нет, один класс — один файл, `if/else` вместо `switch` на две ветки.
- Таймеры не чаще раза в 5 с; DNS и проверка узла — в пуле потоков, результат через `Post`.
- Ничего корпоративного в коде и README: адаптер VPN по умолчанию — `Fortinet`.
- Системные программы (`schtasks`, `powershell`, `cmd`) — по полному пути из `SystemTools`: установщик запускается из
  «Загрузок», и программа с тем же именем рядом с ним выполнилась бы с правами администратора.
- Безопасность — соразмерно утилите (модель угроз — в скилле `selfcheck`, режим pet-проекта): защищаемся от того, до
  чего программа дотягивается сама (сеть, файлы рядом с установщиком в «Загрузках», канал обновления) и от вреда от
  самой программы (стёртое чужое, испорченные конфиги). Локальный процесс того же пользователя — вне модели.
- Из папки установки и прежних папок программа удаляет только свои файлы — имена из `AppIdentity.PayloadFiles`
  (= `installer\payload.txt`), метку `AgentVpnGuard.install` и `.old.exe`, — а саму папку только если она опустела
  (`InstallFolder.RemoveProgramFiles`): чужое в ней пропасть не должно. Установщик принимает папку, если она пустая, с
  меткой (`InstallFolder.IsMarked`), с одними файлами программы (`HoldsOnlyProgramFiles`) или это зарегистрированная
  папка с exe (`IsOurs`). Прежняя зарегистрированная
  папка чистится при `IsOurs`; деинсталлятор чистит папку только с меткой; папка ClaudeVpnGuard чистится, только если
  в ней нет метки AgentVpnGuard.
- `src\app.ico` генерируется скриптом `src\make_icon.py` (нужен Pillow).

## Грабли

- Heredoc в Bash ест обратные слэши — `.cmd` писать python-скриптом, `chr(92)`.
- `.cmd` — CRLF и только ASCII.
- Правило брандмауэра без списка интерфейсов действует на **все** адаптеры, включая VPN. Пустой список
  — это «Claude без сети», а не «без ограничений».
- Блок-правило в брандмауэре Windows сильнее разрешающего: чужое «разрешить» защиту не снимает.
- `INetFwRule.Interfaces` принимает только адаптеры, которые есть в системе сейчас: имя отсутствующего
  даёт `0x80070490`. Поэтому список — из присутствующих, а новый адаптер добавляется по
  `NetworkAddressChanged` (окно около секунды).
- Защитник Windows давал `Trojan:Win32/Wacatac.B!ml` (эвристика) на установщик, скачанный с GitHub:
  неподписанный, с правами администратора и архивом внутри. Сведения о версии (`AssemblyInfo.cs` в
  программе, установщике и деинсталляторе) обязательны; при новом срабатывании — заявка о ложном
  срабатывании на microsoft.com/wdsi/filesubmission.

## Общее с другими pet-проектами

Проект — один из четырёх pet-проектов (AgentVpnGuard, DevMonitor, AgentGlow, AgentProxy), они устроены одинаково:
похожий интерфейс, одинаковые установщик, деинсталлятор, порядок меню и код общих частей.

- **Общие файлы** — одинаковые в AgentVpnGuard, DevMonitor и AgentGlow, отличается только `namespace`:
  `installer\setup\{SetupForm, Installation, InstallTarget, Payload, SetupOption, SetupField,
  InstallRequest, SetupProgram, SetupLog}.cs`, `installer\common\{UninstallRegistration, RunningApp, InstallFolder}.cs`,
  `installer\uninstall\UninstallProgram.cs`, `src\{AboutForm, CrashReportConsent, CrashUploader, UpdateChecker,
  UpdateForm, UpdateRelease, SystemTools}.cs`. `installer\make-payload.ps1` отличается только переменными в начале;
  `build.cmd` и `build-installer.cmd` — тоже, кроме AgentGlow, у которого они свои (рекурсивная сборка `src`, общий
  список исходников для установщика). Поменял общий файл — та же правка в остальных проектах. У AgentProxy часть
  общих файлов расходится осознанно (установка без прав, HKCU, тихий режим) — список в его `CLAUDE.md`;
  `Update{Checker,Form,Release}.cs` одинаковые у всех четырёх (сверка sha256 по `digest` релиза, «Установить сейчас»
  через ShellExecute — окно UAC у программ без прав), своё — `AppIdentity.UpdateSetupArguments` и `UpdateKeeps`. Тесты
  общего кода обновления — в AgentProxy (`tests\csharp\run.cmd`).
- **Своё у проекта:** `src\AppIdentity.cs` (имя, версия, ссылки, пути, `PayloadFiles`, параметры обновления),
  `src\Autostart.cs` (задача Планировщика или ключ Run), `installer\setup\SetupProfile.cs` (тексты, поля, галочки,
  свои шаги, `AfterLaunch`),
  `installer\uninstall\UninstallProfile.cs`, `installer\payload.txt` (что ставится), `src\CrashReport.cs`
  (перехват падений: куда пишет текст ошибки — у каждого свой журнал).
- **Надёжность:**
  - журнал `log.txt` пишет запуск (версия, пользователь, Windows, настройки), шаги запуска и причину
    каждого отказа — по нему «не завелось» разбирается без догадок;
  - `Program.cs` перехватывает падения (`AppDomain.UnhandledException` с
    `[HandleProcessCorruptedStateExceptions]`, `Application.ThreadException`), `CrashReport` пишет
    стек в журнал и показывает окно; отчёт на `AppIdentity.SiteUrl + "crash-report"` — только по
    согласию из установщика (галочка по умолчанию выключена), один раз, без повторов;
  - опасные системные вызовы (COM брандмауэра, драйверы, нативные DLL) не должны молча убивать
    программу: отдельный процесс с таймаутом или перехват плюс метка «прошлый запуск умер здесь»;
  - сбои окружения программа по возможности лечит сама; проблема и починка видны на значке в трее
    (метки ошибки и починки), в подсказке, меню и журнале. Свои проблемы — только в трее и
    уведомлениях, не в основном результате программы.
- **Меню трея:** блок состояния; действия приложения; «Настройки…», «Журнал» (если есть),
  «Запускать при входе в Windows», «Проверить обновление…», «О приложении…»; «Выход».
- **Установщик:** права администратора, выбор папки (по умолчанию `C:\Program Files\<Имя>`), галочка
  автозапуска, сам останавливает запущенную копию, после установки запускает программу. Регистрация
  в «Приложениях» — в HKLM. Деинсталлятор сам закрывает программу и удаляет её данные.
- **Установка поверх любой прежней версии обязана работать** (правило с версии 1.9): установщик сам
  останавливает запущенную копию, заменяет файлы, пересоздаёт задачи Планировщика и записи реестра
  (`/F`, перезапись), настройки старых версий читаются — незнакомые ключи пропускаются, пропавшие берут
  значения по умолчанию, форматы данных остаются читаемыми или переводятся при запуске. Удалять старую
  версию перед установкой пользователь не должен никогда. Перед релизом — установка поверх предыдущего
  релиза и проверка журнала.
- **Любая правка доводится до конца:** версия в `AppIdentity.Version` и трёх `AssemblyInfo.cs`, запись
  в `CHANGELOG.md`, сборка `build-installer.cmd`, проверка Защитником, коммит и push, Release на
  GitHub с установщиком, при необходимости — README, скриншоты в `docs\` и страница на
  aokazantsev.ru/pets.
